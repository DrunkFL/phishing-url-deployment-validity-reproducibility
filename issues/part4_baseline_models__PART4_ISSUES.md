# 第四部分实验问题记录

本文件记录第四部分执行中发现的问题，并在实验结束后补充最终状态。

## 预先识别的问题

### P4-01 模型文件的磁盘占用风险

- **发现**：开始第四部分时 C 盘剩余空间约 9.76 GB；若保存240个内部运行的完整随机森林模型，可能耗尽空间。
- **处理**：全部运行保存参数、种子、阈值、指标和预测概率，只长期保存主重复 `r00` 的模型文件。
- **状态**：已控制；运行期间继续监控磁盘。

### P4-02 S4目标标签误用风险

- **发现**：第三部分S4索引为最终评估保存了目标标签，代码若复用不当可能将其用于调参。
- **处理**：S4只接收已经冻结的S3模型和阈值；模型选择函数的参数中不包含目标数据。
- **状态**：已控制；由合成测试与输出验证继续检查。

### P4-03 完全去重敏感性语料暂不进入主基线

- **原因**：第四部分主问题是比较同一主语料上的S0-S4部署条件；同步运行完全去重版本会使训练量和产物近似翻倍。
- **处理**：本阶段只运行`master`，完全去重语料保留到敏感性与统计分析部分。
- **状态**：研究范围决定，必须在阶段报告中明确说明。

### P4-04 常量及强相关特征

- **发现**：第二部分已发现ISCX的`has_userinfo`为常量，且存在15个高相关特征对实例。
- **处理**：F-All基线保留冻结的35项共同特征；StandardScaler和树模型可以处理常量列，不根据全数据审计提前删列。
- **状态**：已控制；训练后需观察收敛警告，并在SHAP阶段处理相关特征替代问题。

## 运行时问题

运行时警告和失败首先写入 `logs/runtime_issues.jsonl`，完整实验结束后在此处汇总。

### P4-05 部分范围烟雾运行的汇总器错误

- **发现**：仅运行`PhiUSIIL/S0/r00`时，三类模型均已成功训练和保存，但汇总器假设S4结果必然存在，在汇总阶段触发`KeyError: source_dataset`。
- **影响**：不影响已经写入的模型、指标、调参记录和预测文件，只使该次命令以错误码结束。
- **处理**：汇总器现允许S4为空，并生成带固定表头的空S4结果表；完整运行仍要求最终S4行数满足验证约束。
- **状态**：已解决，修复后需重新运行测试和部分范围汇总。

### P4-06 中文路径在PowerShell重定向日志中再次乱码

- **发现**：异常堆栈经PowerShell管道重定向后，实验根目录的中文字符显示为乱码；实际文件读写路径正确。
- **处理**：实验程序自身的JSON、CSV和Markdown继续显式使用UTF-8；正式运行通过Python直接写UTF-8日志，避免依赖重定向后的路径文本作为证据。
- **状态**：已控制，不影响数据或模型文件。

### P4-07 同类模型的运行时间存在明显系统波动

- **发现**：PhiUSIIL随机森林多数运行约56-64秒，但少数运行达到约83-113秒；同一时段LR和XGBoost也同步变慢，模型指标与警告状态正常。
- **判断**：更可能来自系统负载、CPU调度或温度/功耗变化，而不是特定划分或模型故障。
- **处理**：保留所有原始计时，不删除慢运行；论文涉及效率时报告多次运行分布或中位数，并说明共享桌面环境下绝对耗时的限制。
- **状态**：已记录。最终报告使用10次运行分布和中位数，不以单次耗时作为结论。

### P4-08 结果分析阶段的ISCX关联键不唯一

- **发现**：首次运行结果分析脚本时，仅使用`source_row`把第三部分索引与ISCX特征元数据关联，触发一对一关联失败。ISCX由多个源类别文件组合，不同文件可复用相同行号。
- **影响**：错误发生在训练全部完成后的附加分析阶段，未修改模型、预测或原始指标；失败运行没有生成最终分析报告。
- **处理**：关联键改为`source_row + label`，与现有预测关联方式一致，并继续执行一对一校验。
- **状态**：已解决并验证。重新运行后分析脚本成功完成，新增审计文件已写入`results/analysis_manifest.csv`并固定哈希。

### P4-09 ISCX严格分组结果被少数大实体显著影响

- **发现**：ISCX的S2/S3在部分重复中出现高ROC-AUC但低Macro-F1和高FPR。误报高度集中于数据集中标为良性的`torcache.net`和`extratorrent.cc`。`torcache.net`约有1367行，在异常测试分区中通常贡献1300条以上误报；其作为第一大误报实体时，中位误报占比为91.2%。
- **解释**：分组协议要求整个host或注册域名进入同一分区。当该大实体进入验证集或测试集时，会显著改变阈值选择或测试误报率。数据年代、实体语义和标签标准也可能参与，但未经独立核验不能直接称为错标。
- **影响**：ISCX S2的Macro-F1均值/标准差为LR 0.8873/0.1107、RF 0.9476/0.0953、XGB 0.9510/0.0821；S3分别为0.8661/0.1254、0.9578/0.0586、0.8978/0.1167。
- **处理**：全部异常重复原样保留；新增阈值稳定性、实体误报集中度和大实体分区审计，不根据测试结果重新划分或改阈值。
- **状态**：已识别并控制，必须在论文结果与威胁有效性部分重点披露。

### P4-10 双向S4出现概率饱和与近乎全阳性预测

- **发现**：PhiUSIIL训练后迁移到ISCX，主过滤集Macro-F1为0.1704-0.2330，FPR为0.9408-1.0000；ISCX训练后迁移到PhiUSIIL，Macro-F1为0.2878-0.2948，FPR为0.9999-1.0000。多数目标样本的钓鱼概率接近1。
- **解释**：域名过滤前后现象均存在，不能由直接URL/host/domain重叠解释；第二部分发现的强来源分布漂移与采集/标签差异更可能是主因。
- **处理**：保留过滤前后结果和逐类别概率分位数；不使用目标标签重新校准阈值。后续SHAP来源稳定性分析需围绕该失效展开。
- **状态**：实验结果有效，但模型跨来源不可用；论文不得把内部高分外推为普遍泛化能力。

### P4-11 均值会掩盖ISCX的多峰重复分布

- **发现**：部分ISCX S2/S3重复接近满分，另一些重复受大实体影响而显著下降，均值不能代表任何一类典型运行。
- **处理**：除均值和bootstrap区间外，报告标准差、最小值、最大值、逐重复结果和实体集中度。事后诊断规则共标记32个S2/S3模型运行，但这些标记不用于排除结果。
- **状态**：已控制，论文表格和图形应展示重复分布。

### P4-12 S4主目标队列会随来源划分重复变化

- **发现**：首次最终人工复核错误地假设主S4队列在10次重复中固定不变。实际上，每次重复的S3来源训练/验证域名不同，因此需要从目标集中排除的重叠域名也不同。PhiUSIIL到ISCX的主队列为41,108-41,919行；ISCX到PhiUSIIL为233,296-234,478行。
- **影响**：不同模型在同一重复中使用相同目标队列，模型间比较仍成立；跨重复结果同时包含模型/来源划分变化和目标队列轻微变化，不能视为只改变模型种子的纯稳定性估计。
- **处理**：新增`s4_cohort_comparability.csv`。所有重复主队列的共同交集分别为40,656行和233,286行，后续跨种子SHAP来源稳定性应在该固定共同队列上计算。
- **状态**：已识别并控制；模型与原始S4指标无需修改，论文中必须披露队列变化。
