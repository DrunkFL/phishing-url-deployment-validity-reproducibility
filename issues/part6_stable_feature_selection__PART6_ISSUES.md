# 第六部分实验问题记录

## 预先识别的问题

### P6-01 测试解释反向进入特征选择

- **风险**：直接使用第五部分test/external SHAP构造F-Stable会造成信息泄漏。
- **控制**：第六部分重新在每个外层train内部建立分组内层划分；选择程序不读取第五部分运行目录或S4分配文件。
- **状态**：代码与输出验证必须持续检查。

### P6-02 方向为零时的一致率分母

- **风险**：把常量或零相关运行计入分母会偏离论文定义；只剩极少有效运行时也应透明披露。
- **控制**：只用非零方向计算一致率，同时保存有效和排除运行数；无有效方向的特征不能入选。
- **状态**：已写入协议和单元测试。

### P6-03 相关特征的归因替代

- **风险**：相关特征可能在Top-k边界相互替换，使单项频率低估特征组稳定性。
- **控制**：本部分保留全部频率与排名，不事后合并特征；相关特征组分析留给敏感性实验。
- **状态**：后续持续处理。

### P6-04 特征子集为空或过小

- **风险**：严格方向与频率阈值可能产生无法训练的集合。
- **控制**：不设置基于测试结果的补位规则；若发生则停止该组合、记录事实并重新审视预设规则。
- **状态**：运行时检查。

## 运行时问题

### P6-05 首次烟雾测试日志目录缺失

- **发现**：首次命令中的`Tee-Object`因`logs`目录尚未建立而报错；管道中的Python进程仍完成了ISCX/r00/LR的`i00-i01`两个检查点。
- **处理**：建立标准目录后重新运行；脚本识别并跳过两个完整检查点，从`i02`继续。
- **结果**：10/10烟雾运行完成，未覆盖或丢失结果，说明逐运行恢复机制有效。
- **状态**：已解决。

后续运行警告、失败和恢复情况将在本文件继续追加。

### P6-06 用户要求暂停完整选择任务

- **发现**：任务在PhiUSIIL/r06/RF期间收到暂停请求。
- **处理**：先结束等待句柄，再向运行会话发送中断；确认无残留Python进程后按`complete.json`统计进度，并对完整结果执行阶段性聚合。
- **结果**：保存206/600个完整选择运行和20/60个完整特征集；最后完整项为r06/RF/i05，未完成的i06将在恢复时重算。
- **状态**：已安全暂停，恢复命令见`PAUSE_CHECKPOINT_20260905.md`。

### P6-07 暂停后恢复与完整性确认

- **发现**：恢复时已有206/600个选择检查点；随后完成剩余394个选择运行和120个降维模型运行。
- **处理**：依赖`complete.json`跳过完整项，对不完整项重新计算；最终逐文件验证训练侧样本边界和外层测试ID/标签。
- **结果**：600/600选择、60/60特征集、120/120降维模型和180条对比指标均完整；验证为`PASS`，没有警告文件。
- **状态**：已解决。

### P6-08 方向一致性条件的额外筛选作用有限

- **发现**：主配置中821个特征项满足频率阈值，方向阈值只额外拒绝7项，且均为PhiUSIIL随机森林的`letter_count`。
- **影响**：不能把方向一致性包装成已经显著改善预测性能的主要创新；当前主要筛选动力来自Top-k频率。
- **处理**：保留方向条件作为归因异常审计，并在报告中披露频率单独规则的敏感性结果。
- **状态**：已纳入结果解释。

### P6-09 特征集合稳定不等于预测性能提升

- **发现**：F-Stable明显减少特征，并在4/6组提高集合Jaccard，但Macro-F1并未普遍提高。ISCX LR/RF和PhiUSIIL LR出现下降，ISCX XGB平均改善但置信区间跨0。
- **影响**：论文结论必须定位为“紧凑性与可重复性权衡”，不能声称稳定筛选总能提升准确率。
- **处理**：同时报告F-All、F-Single和F-Stable的配对差值、bootstrap区间及未校正Wilcoxon结果。
- **状态**：已纳入正式报告。

### P6-10 微秒级效率测量存在噪声

- **发现**：线性模型和小批量推理耗时接近计时器与系统调度噪声量级，个别降维配置的SHAP耗时未下降。
- **影响**：不能依据单次微秒级差异宣称精确部署加速倍数。
- **处理**：效率结论限定为特征输入缩减和树模型解释耗时的经验变化；保留10次重复的均值、标准差、最小值和最大值。
- **状态**：已披露。
