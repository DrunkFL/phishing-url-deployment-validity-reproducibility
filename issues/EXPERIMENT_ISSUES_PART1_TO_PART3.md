# 前三部分实验问题记录与处理报告

记录日期：2026-09-02  
适用范围：第一部分“环境与数据准备”、第二部分“URL 清洗与特征提取”、第三部分“S0-S4 数据划分”

## 1. 记录目的

本报告记录实验执行期间出现的工程问题、数据质量问题、方法学风险及当前处理方式。问题按以下状态区分：

- **已解决**：已修复并通过测试或审计，不再影响现有输出。
- **已控制**：风险未被消除，但已通过固定流程、单独语料或结果披露控制其影响。
- **待后续处理**：需要在模型训练、SHAP 分析或论文写作阶段继续处理。

本实验未修改原始数据，未访问数据集中的 URL，也未隐瞒失败记录。所有清洗、特征和划分产物均与原始数据分开保存。

## 3. 第一部分：环境与数据准备

### P1-01 ISCX 官方数据入口不可用及镜像来源限制

- **发现**：ISCX 官方注册页面返回服务器错误，并要求提交个人信息。
- **处理**：未提交个人信息。改用公开 GitHub 仓库 `Raj-S-Singh/Real-Real-Time-Detection-of-Malicious-URLs-using-Machine-Learning`，固定到提交 `9f8ffd697ce3250a7db5f4bce9c4870722b70ef5`。
- **证据**：镜像文件名、类别和数据规模与官方描述及独立代码相符，但无法与官方压缩包进行逐字节比对。
- **状态**：**已控制**，来源置信度为中等。
- **论文处理**：方法部分明确写出镜像、提交号和访问日期；局限性中说明无法验证与官方归档的字节级一致性。镜像未明确提供数据许可，在许可确认前不对外重新分发压缩包。

### P1-02 仅含预计算特征的数据镜像不适合作为实验输入

- **发现**：检索到的 Hugging Face 和 Kaggle 镜像只包含预计算特征表，没有原始 URL。
- **处理**：保存在 `data/reference/feature_only_mirrors/` 作为参考，未纳入实验。
- **状态**：**已解决**。
- **原因**：使用第三方预计算特征会失去清洗可追溯性，并可能引入未知的数据泄漏和特征定义差异。

### P1-03 PhiUSIIL 首次下载中断

- **发现**：首次下载因网络缓慢中断，产生 4,489,216 字节的部分文件。
- **处理**：部分文件保存在 `logs/download_failures/phiusiil_phishing_url_dataset.partial_20260902_152105`；随后重新下载官方压缩包并通过哈希验证。
- **状态**：**已解决**。
- **论文影响**：无，失败文件未作为实验输入。

### P1-04 Python 依赖下载不稳定

- **发现**：PyPI 连接速度较慢。
- **处理**：仅将清华镜像用于包传输，依赖版本仍在本地固定；`pip check` 已通过。
- **状态**：**已解决**。
- **复现要求**：后续实验继续使用已冻结环境，不随意升级包版本。

### P1-05 Windows 中文路径日志乱码

- **发现**：终端显示中文路径时曾出现乱码，但内部路径解析正确。
- **处理**：日志统一使用 UTF-8 重写并重新检查。
- **状态**：**已解决**。

### P1-06 PhiUSIIL 标签语义与统一实验标签相反

- **发现**：PhiUSIIL 原始标签为 `1=legitimate`、`0=phishing`，与实验统一定义 `0=benign`、`1=phishing` 相反。
- **处理**：第二部分读取时显式重编码，并在数据字典及审计报告中记录。
- **状态**：**已解决，但属于高风险实现细节**。
- **后续要求**：模型输出、混淆矩阵和 SHAP 类别解释均以统一标签为准，任何新脚本不得直接沿用原始标签含义。

### P1-07 ISCX spam 文件换行格式异常

- **发现**：`spam_dataset.csv` 主要使用 CR-only 换行。
- **处理**：已在来源检查中记录。当前二分类主实验未使用该类别。
- **状态**：**已控制**。
- **后续要求**：若扩展到多分类实验，必须使用兼容该换行格式的解析方式并重新核验行数。

## 4. 第二部分：URL 清洗与特征提取

### P2-01 URL 解析库版本兼容和 hxxp 正则问题

- **发现**：初始单元测试发现 `tldextract 5.1.3` 使用 `registered_domain`，而不是新版接口 `top_domain_under_public_suffix`；同时，早期 hxxp 单斜杠识别正则范围过窄。
- **处理**：按固定依赖版本修正接口并扩大规范化测试覆盖。
- **验证**：最终 13 项测试全部通过。
- **状态**：**已解决**，修复发生在正式处理数据之前。

### P2-02 Public Suffix List 的可复现性

- **发现**：初始实现依赖包内 PSL，但没有单独冻结准确快照。
- **处理**：保存 `resources/public_suffix_list_tldextract_5.1.3.dat`，SHA-256 为 `91aeeed5dfc84a53265d95cfbb0e7bb52df8ed75a24a27568817cd69578a2f80`；关闭网络更新和 private suffix。
- **状态**：**已解决**。
- **论文影响**：保证注册域名提取不会因后续 PSL 更新而悄然变化。

### P2-03 主语料定义在执行中得到纠正

- **发现**：早期只生成了完全去重候选语料，但当前研究设计要求 S0-S3 主实验保留同标签重复项，仅删除规范化 URL 的异标签冲突；完全去重数据应作为敏感性分析。
- **处理**：新增 `conflict_cleaned_master`，同时保留去重敏感性语料。
- **状态**：**已解决**。
- **论文影响**：主实验能够观察随机划分中的重复泄漏效应，敏感性实验用于判断结论是否依赖重复样本。

### P2-04 URL 重复和规范化后标签冲突

- **PhiUSIIL**：输入 235,795 行；完全重复额外 425 行；规范化重复额外 1,138 行；发现 1 个异标签规范化组、涉及 2 行；完全去重后 234,656 行。
- **ISCX 二分类数据**：输入 45,343 行；完全重复额外 9 行；规范化重复额外 119 行；未发现异标签规范化组；完全去重后 45,224 行。
- **处理**：异标签规范化组不进入主语料；同标签重复保留在主语料、从敏感性语料中删除。
- **状态**：**已控制**。

### P2-05 跨数据集 URL 不重叠，但注册域名重叠

- **发现**：两个清理语料的规范化 URL 交集为 0，但注册域名交集为 123。
- **处理**：第三部分增加 host-disjoint、registrable-domain-disjoint 和 S4 域名过滤。
- **状态**：**已控制**。
- **论文影响**：不能仅凭 URL 不同就声称训练集与测试集没有实体级关联。

### P2-06 35维特征存在大量特征向量碰撞

- **PhiUSIIL 主语料**：235,793 行中只有 88,106 个唯一特征向量；额外重复向量 147,687 行；402 个异标签特征向量组，涉及 36,953 行。
- **ISCX 主语料**：45,343 行中有 42,713 个唯一特征向量；额外重复向量 2,630 行；无异标签特征向量组。
- **解释**：这不是原始 URL 的标签冲突，而是多个不同 URL 被有限的 35 项离线特征映射为同一数值向量。
- **处理**：不据此删除或重标样本，保留统计并在误差分析中关注这些碰撞组。
- **状态**：**已控制，需在论文讨论中披露**。
- **论文价值**：该现象可用于说明只依赖词法特征的表示上限，也能支持后续对稳定解释与错误案例的分析。

### P2-07 ISCX 的 `has_userinfo` 为常量特征

- **发现**：ISCX 中 `has_userinfo` 全部为 0。
- **处理**：为保持两个数据集共同特征模式，特征文件中暂时保留。
- **状态**：**待后续处理**。
- **后续要求**：常量检测与删除只能在每个训练折内部拟合，不能用全数据提前选择特征。

### P2-08 高相关特征及 SHAP 归因替代风险

- **发现**：两个主语料合计出现 15 个 `|Spearman rho| >= 0.95` 的特征对实例。
- **风险**：相关特征可能在不同种子或数据来源中相互替代，造成单特征 SHAP 排名波动，即使模型预测相近。
- **处理**：未根据全数据审计直接删特征，以免引入选择泄漏。
- **状态**：**待第五、六部分处理**。
- **后续要求**：同时报告单特征稳定性、相关特征组稳定性和预测性能，避免把排名交换简单解释为模型不可靠。

### P2-09 跨来源特征分布漂移明显

- **发现**：良性样本中的绝对标准化均值差较大，例如 `subdomain_depth=6.597`、`letter_count=3.303`、`url_char_entropy=2.555`、`url_length=2.548`、`path_length=2.517`；全样本范围的部分路径特征同样明显漂移。
- **解释**：数据来源、采集方式和 URL 构成可能形成强烈的来源指纹。
- **状态**：**待后续处理，属于核心方法学风险**。
- **论文处理**：S4 下降只能表述为“在这两个公开来源之间的迁移表现”，不能直接声称代表所有真实世界环境。后续应结合分布图、错误案例和来源稳定特征进行解释。

### P2-10 特征范围与人工核查的局限

- **实现范围**：仅提取 35 项确定性离线词法和结构特征；未使用 WHOIS、DNS、网页 HTML、证书、可疑词词典或品牌不匹配特征。
- **原因**：减少网络状态、查询时间和第三方服务造成的不可复现性，也降低明显的语义泄漏风险。
- **人工核查**：抽查 40 个确定性离线样本，未发现解析或计数错误；未访问 URL，也不能验证数据集标签真实性。
- **状态**：**已控制，构成研究边界**。

### P2-11 尚未检测近似或语义重复

- **发现**：当前只检测完全相同和保守规范化后的重复，未执行编辑距离、模板相似度或语义近重复检测。
- **状态**：**待后续决定**。
- **论文处理**：至少在局限性中披露；若后续时间允许，可增加近似重复阈值敏感性实验，但不应临时改变已冻结主划分。

## 5. 第三部分：S0-S4 数据划分

### P3-01 初始分组划分算法速度与重复性问题

- **发现**：`StratifiedGroupKFold` 在约 23.5 万个 URL 分组上速度过慢；在一个类别构成同质的合成测试中，不同种子还可能产生相同划分。
- **处理**：在正式 S1 输出写入前终止该方案，改为预先规定的加权贪心分组：先按种子打乱同级分组，再按组大小排序，将整个组分配到使良性、恶意和总样本目标相对平方误差增量最小的分区。
- **验证**：保留 10 个固定种子；临时 S0 后来由正式流程覆盖。
- **状态**：**已解决**。

### P3-02 分组不可拆分导致比例只能近似

- **发现**：注册域名或主机组必须整体进入一个分区，无法始终精确达到 70/15/15。
- **数据特征**：PhiUSIIL 最大注册域名组含 5,754 行；ISCX 最大主机/域名组含 1,367 行。
- **结果**：实际比例与目标比例的最大绝对偏差为 0.0068，即 0.68 个百分点。
- **状态**：**已控制**。
- **论文处理**：报告每个分区的实际样本数和类别比例，不只写目标比例。

### P3-03 不同划分协议消除的重叠层级不同

- **主种子 r00 的训练-测试重叠**：

| 数据集 | 协议 | URL 重叠 | host 重叠 | 注册域名重叠 |
|---|---:|---:|---:|---:|
| PhiUSIIL | S0 | 240 | 1,552 | 2,266 |
| PhiUSIIL | S1 | 0 | 1,339 | 2,164 |
| PhiUSIIL | S2 | 0 | 0 | 1,060 |
| PhiUSIIL | S3 | 0 | 0 | 0 |
| ISCX | S0 | 23 | 696 | 682 |
| ISCX | S1 | 0 | 687 | 682 |
| ISCX | S2 | 0 | 0 | 40 |
| ISCX | S3 | 0 | 0 | 0 |

- **解释**：URL-disjoint 不等于 host/domain-disjoint，host-disjoint 也不等于 domain-disjoint。
- **状态**：**已控制，并构成后续实验的重要自变量**。
- **论文处理**：S0-S3 表示不同部署条件，不应机械描述成从“错误”到“正确”的单向等级；后续性能下降也不能自动等同于泄漏证据。

### P3-04 部分 ISCX 分组划分跨种子变化较小

- **发现**：所有非主重复均与 r00 不同，但 ISCX 的部分 S2/S3 重复中，变化样本比例最低约为 2%-3%。
- **原因**：实体数量较少且大组较多，分组完整性限制了随机变化空间。
- **状态**：**已控制**。
- **后续要求**：解释稳定性时同时报告划分差异程度，避免把高度相似的重复当作完全独立证据。

### P3-05 S4 域名过滤具有方向不对称性

- **PhiUSIIL -> ISCX**：目标集 45,343 行；过滤前共享 host 为 9、共享注册域名为 112；排除 4,235 行（9.34%），主外部测试集剩余 41,108 行。
- **ISCX -> PhiUSIIL**：目标集 235,793 行；过滤前共享 host 为 9、共享注册域名为 117；排除 1,411 行（0.60%），主外部测试集剩余 234,382 行。
- **验证**：过滤后两个方向、两个语料版本和所有重复的 URL、host、注册域名重叠均为 0。
- **状态**：**已控制**。
- **论文处理**：同时报告未过滤与域名过滤后的 S4 结果，并报告排除比例；不把两个迁移方向视为对称难度。

### P3-06 S4 标签隔离要求

- **发现**：S4 目标标签为评估所需，已保存在数据中，但存在被误用于调参、阈值选择或特征选择的风险。
- **状态**：**待第四部分严格执行**。
- **要求**：所有预处理、超参数、阈值和特征选择只能使用来源训练/验证数据；目标域标签只在最终评估时读取。

### P3-07 输出规模和磁盘空间

- **发现**：第三部分分配文件约 1.2 GB，第三部分目录总计约 1.17 GB；记录时 C 盘可用空间约 9.85 GB。
- **状态**：**待持续监控**。
- **后续要求**：模型预测和 SHAP 结果优先保存必要的压缩表格；避免为每次试运行重复保存完整特征副本。

## 6. 已完成验证

- 第二部分最终 13 项单元测试通过。
- 第三部分 3 项测试通过。
- 360 项内部零交集约束全部通过。
- S4 域名过滤后，两个方向的 URL、host 和注册域名重叠均为 0。
- 29 个第三部分输出文件哈希与清单一致。
- 40 个离线样本人工核查未发现特征解析或计数不一致。

这些验证只证明实现与预设协议一致，不证明公开数据标签完全正确，也不消除数据来源偏差。

## 7. 后续实验必须继承的控制措施

1. 输入列必须按冻结的特征字典选择，禁止把 URL、标签、来源名或分组标识误作为特征。
2. 缺失处理、缩放、常量删除和特征选择都只能在训练数据内拟合。
3. 直接使用第三部分固定索引，不在模型阶段临时重新划分。
4. 主语料与完全去重敏感性语料分别报告，不混合结果。
5. S4 目标标签不得参与调参、阈值选择和特征选择。
6. S4 同时报告未过滤和域名过滤结果，并列出实际排除比例。
7. SHAP 稳定性分析必须考虑高相关特征间的归因替代，并结合特征组稳定性。
8. 跨来源结果必须结合分布漂移解释，不使用“普遍泛化能力”等过强结论。
9. 继续记录失败运行、随机种子、运行时间、版本、哈希和磁盘占用。
10. 投稿前再次核实 ISCX 数据来源与许可；未确认前不公开重新分发原始镜像。

## 8. 建议用于论文的客观表述

- **数据来源**：ISCX-URL2016 原始 URL 文件从固定提交的公开镜像恢复；其文件结构和规模与公开描述一致，但未能与官方归档进行字节级核验。
- **特征边界**：研究使用确定性的离线 URL 词法与结构特征，以提高复现性；因此结论不覆盖网页内容、DNS、证书或注册信息特征。
- **迁移边界**：外部迁移结果反映 PhiUSIIL 与 ISCX 两个公开数据来源之间的分布变化，不应直接外推到所有现实网络环境。
- **重复边界**：主分析保留同标签重复项以评估不同实体隔离协议，另使用完全去重语料进行敏感性验证。
- **表示边界**：不同 URL 可能共享同一 35 维特征向量；该表示碰撞是离线词法特征的信息限制，而非原始 URL 的直接标签冲突。
